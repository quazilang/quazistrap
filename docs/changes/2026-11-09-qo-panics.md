# A panic in a qoroutine is reported by `join`

Audience: language users and compiler developers.

D-019 round 2 (В2) decided that a panic inside a qoroutine is delivered as an
error from `join` instead of ending the program.

- `Qoroutine[T].join()` now returns `Result[T, QoroutineError]`;
  `QoroutineError.Panicked` is the only variant. Existing callers add
  `.unwrap()` (or match the error).
- The prelude panic handler prints `qoroutine panicked at '...'` when it runs
  on a qoroutine (found through the stack arena, no thread-local storage),
  then `__qo_abandon_on_panic` marks the task panicked and switches to the
  worker for good. The abandoned stack is never resumed; values it still owned
  are not cleaned up (no unwinding). Its slot returns to the arena on `join`.
- Outside qoroutines a panic still prints `thread 'main' panicked` and exits
  with status 101.

Verification: `scripts/check_qoroutines.py` runs 30 qoroutines of which 10
panic: `join` reports 10 errors, the other results add up, stderr has ten
qoroutine panic messages, and a final panic on the main thread exits with 101.
