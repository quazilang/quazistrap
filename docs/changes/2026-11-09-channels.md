# Built-in `Channel[T]`

Audience: language users and compiler developers.

D-019 decided on one built-in `Channel[T]` with `send`, `receive` (returning
`Option[T]`) and `close`, shared by qoroutines and OS threads, without `<-`
operators or `select`.

`prelude/src/qoroutine.qz` now provides it: a 64-byte block (spin lock,
owner count, capacity, count, head, closed flag, buffer of 8-byte slots).
`Channel.new(capacity)` (typed by the declaration, `const ch: Channel[i64] =
Channel.new(8)`), `clone()` adds an owner, the automatic `free` hook drops
one and releases the block with the last owner. `send` waits while full and
panics once closed; `receive` waits while empty and returns `None` once
closed and drained. Waiting uses `__qo_yield`, so a qoroutine gives its worker
to others and other threads yield their time slice.

Limits: values are one raw slot, so channels carry plain scalars until owned
values can be stored; `Channel[i64].new(...)` (explicit type arguments on a
static call) does not parse; `Channel.free` is reachable from every program
as a destructor root (the scheduler is not).

Verification: `scripts/check_qoroutines.py` sends 2000 values from two
producer qoroutines through an 8-slot channel to the main thread, runs a
producer/consumer/closer pipeline through a 4-slot channel, and checks the
`None` after close and drain (5 native runs and `--jit`).
