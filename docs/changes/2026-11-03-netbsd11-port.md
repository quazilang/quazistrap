# NetBSD 11.0/amd64 port: validated checkpoint and remaining work

**Checkpoint:** 2026-11-03. **Compiler:** `qz 0.26.0` (`feature/netbsd11`).
**Validation host:** `titago`, NetBSD 11.0/amd64, native `cargo build --release`.
**Maturity:** experimental / work in progress; not a production-readiness claim.

## Scope and verified behavior

The new native target is `x86_64-netbsd`. The built-in ELF linker produces an
executable for NetBSD with `/usr/libexec/ld.elf_so`, a NetBSD ABI note, and a
`DT_NEEDED` dependency on `libc.so.12`. An external-linker path is also
available for native C dependencies; its NetBSD `.note.netbsd.ident` support
was tested with example 20. NetBSD syscalls are **not** mapped to Linux
`@syscall` numbers: direct NetBSD `@syscall` lowering is intentionally disabled
until an explicit NetBSD syscall table/ABI is implemented.

## Known defects / incomplete coverage

### NETBSD-001: `match` with diverging first arm returns an incorrect value

**Open; compiler correctness bug.** With the NetBSD native codegen, a value-
producing `match` of the form

```quazi
ret match result {
    Ok(_) => panic("unexpected Ok"),
    Err(n) => n,
};
```

returns `0` when `n` should be `2`. The otherwise equivalent ordering with
`Err(n) => n` first returns `2`. The same mismatch occurs with **both**
NetBSD built-in and external linkers, so it is not isolated to the built-in
ELF linker. The equivalent Linux test produced `2`. QZI disassembly showed
an apparently correct branch; **the exact cause in native lowering/codegen
is not yet established**.

The `Result.unwrap_err()` method in `prelude/src/result.qz` has its `Err`
branch first as a verified workaround: scalar and enum payload probes both
returned `2` on NetBSD. The INI regression test uses an explicit nested
`match`. Neither workaround resolves the general `panic`-first bug.

**Regression goal:** run the four-case matrix (`literal_first`,
`call_first`, `panic_first`, `panic_last`) through both NetBSD linker paths;
all cases must produce `2`. Compare QZI and native object disassembly, then
fix codegen and add a permanent automated regression test. A previous
experimental change to `src/bytecode/codegen.rs` (Round 15) did **not** fix
the bug and was reverted; do not reapply it as a fix.

### NETBSD-002: Several example targets cannot compile (`S10`)

**Open; shared ownership/std limitation, not evidence of a NetBSD-only bug.**
The six failed QZI compilations in the latest audit were:

- `26-http-client-server`: `http-server`, `http-client`, `http-url-client`
- `30-dynamic-libraries`: `dynamic-libraries` (use of moved `opened`)
- `31-udp-echo`: `udp-server`, `udp-echo`

HTTP code in `std.net` uses owned contiguous-container elements and reference
provenance that the current borrow checker refuses; eager module analysis
also exposes these errors while compiling UDP. The dynamic-library example
has a separate move error and was not validated for full `dlsym`/indirect-call
and cleanup runtime behavior. These targets are also not established as
working on Linux/Windows at this checkpoint; do not bypass `S10` or introduce
dangling references to force NetBSD green.

**Plan:** address ownership/container capabilities and HTTP/UDP in a separate
cross-platform effort; diagnose the dynamic library example's ownership and
indirect-call/cleanup semantics independently.

### NETBSD-003: Remaining platform API coverage

**Unverified or incomplete, not all confirmed bugs.** Fully validate
`std.process`, thread creation/join (only yield/sleep were smoke-tested),
crash/backtrace handling, and terminal raw-mode behavior. Formalize the
NetBSD `@syscall` mapping before enabling direct syscalls. NetBSD available
RAM currently uses a `free + inactive` estimate, **not** Linux
`MemAvailable` semantics. The `mio` dependency emits a linker warning about
compatibility `__kevent50()`; confirm its modern `kevent()` use during
upstream dependency maintenance. No global warning suppression is required.

## Verification and reproducibility

Keep all generated test sources, binaries, and reports **outside the repository**
(e.g. `~/quazi-tests/netbsd`). Avoid committing `.core`, `.qzi`, native smoke
executables, logs, or experimental patches. `src/backend/builtin_netbsd_linker.rs`
is real source code and **must be tracked** despite initially appearing as `??`
in `git status`.

On the native NetBSD host, with the locally supplied external audit script:

```fish
cd ~/quazistrap
cargo build --release
cargo test --release

mkdir -p ~/quazi-tests/netbsd
python3.11 ~/Downloads/verify_examples_all_v3.py \
    --repo ~/quazistrap \
    --target x86_64-netbsd \
    --output ~/quazi-tests/netbsd/audit

cd ~/quazistrap/examples/33-ini-library
../../target/release/qz test
```

The runner's `RUN_PASS` means that an executable/test suite was **actually
executed**; `BUILD_PASS` alone is only successful compilation. Interactive
examples need the runner's input/PTY adapters. Preserve failure logs and QZI
/ machine-code artifacts outside the source tree for investigation.

## Merge / release criteria

1. Commit this checkpoint as **experimental NetBSD 11.0 support** with this
   open-issues record; do not advertise full std or all-example parity.
2. Resolve NETBSD-001 with a compiler regression test and keep
   `Result.unwrap_err()` behavior correct for scalars and enum payloads.
3. Resolve NETBSD-002 via safe, cross-platform ownership/std changes and
   rerun all configured example targets on Linux, Windows and NetBSD.
4. Exercise the remaining system APIs in NETBSD-003 and verify the final
   combined compiler + installed std revision on real hosts.
5. A separate repository may contain the installed Quazi std at
   `~/.quazi/std`; commit its changes **in that repository** as well and
   record corresponding revisions. Do not assume the compiler-repo commit
   contains the std implementation.

**Compatibility:** Existing Linux and Windows codegen paths are intended to
remain unchanged by this NetBSD port, but full final-tree regressions on
both platforms are required before considering the port release-ready.
