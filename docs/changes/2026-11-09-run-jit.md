# Experimental `qz run --jit`

Audience: language users and compiler developers.

Maintainer decision D-019 round 2 (В5) asked for a real, minimal JIT behind an
experimental flag. `qz run --jit` now compiles the program as usual, links it
with the built-in linker into an in-memory image (`link_elf_image`) and runs it
inside the `qz` process; no executable is written to disk.

How it works (`src/jit.rs`, Linux x86-64 only):

- The built-in linker produces a static ELF executable at fixed addresses
  (base `0x400000`), with no interpreter and no dynamic section.
- Each `PT_LOAD` segment is mapped at its link address with
  `MAP_FIXED_NOREPLACE`, so a collision with `qz`'s own mappings is reported
  as an error instead of overwriting memory. Segment protections are applied
  afterwards (executable segments are not writable).
- Linking stores the image instead of writing a file, so the build finishes
  normally (temporary C objects are removed, `-s` has nothing to strip); the
  shared run step (`run_artifact` in `main.rs`) then executes it.
- A fresh 8 MiB stack receives `argc`, `argv` (the would-be output path),
  the current environment as raw bytes (non-UTF-8 entries are preserved) and an
  empty auxiliary vector. SIGPIPE, SIGSEGV and SIGBUS return to their default
  dispositions, as after `exec` (`qz`'s Rust runtime changes them), and control
  jumps to the entry point exactly as the kernel would start `_start`.
- The program ends the process itself, so `qz` exits with the program's exit
  status (panics exit with 101).

Limits: only Linux targets linked by the built-in linker. `--jit` with an
external linker, archives, shared libraries or `libc = true` is rejected with
"qz run --jit requires the built-in linker". Other host systems report that
the JIT is Linux x86-64 only. The dynamic import/load API discussed in В5 is
future work.

Related fix: returning from `main` and `quazi.exit` on Linux now use
`exit_group` instead of `exit`, so ending the program ends every thread of the
process (matching `ExitProcess` on Windows and `exit(3)` on NetBSD). Under
`--jit` this also ends `qz`'s own threads.

Verification: `scripts/check_jit.py` checks stdout, arguments, exit status,
a non-UTF-8 environment entry, SIGPIPE on a closed stdout pipe (fails before
the signal reset), panic status, the absence of an output binary, the external-linker guard and
that plain `qz run` still writes and runs an executable. Unit tests cover ELF
program-header parsing and the initial stack layout.
